## Key Decisions

- **Measure at the LINE level, not the header.** Consensus from Ivan, Zack, Bryan, and Dave Bishop. The line is the granular truth; the header can always be rolled up from lines, but not vice-versa. Three lines on one order = three potential misses, not one.
  - A line counts as a **single miss** even if it was postponed/hit multiple times — but the drill-down must show each individual reason and its day-impact.
- **Drill-down is the core new capability.** From a reason-by-failure view, click into a line to see the full revision log: every promised-date change, the reason code for each, days moved, and status at the time.
- **Fix reason codes at the source (JDE), not in Excel.** Today reclassifications are done manually in a SharePoint Excel file, so Power BI (which pulls the raw JDE code) disagrees with the "corrected" numbers. Goal: everyone works off one repo.
  - Ivan initially wanted to edit the JDE **ledger** directly. Zack pushed back — a ledger is an immutable audit history; better to build a **custom JDE table/field** (custom change log or reason-code field) plus a **comment/context field**. To be discussed with IT.
- **Exclude blank actual-ship-date orders** (the old "use last-modification-date" fallback caused closed months to shift — fails ISO-certified reporting). Instead: only count good-issued orders, i.e. **next status > 570 with a blank ship date is excluded**.
- **Exclude freight / descriptive lines** (line types FS, F8.E, text lines). Keep only item lines (line type S).

## Requirements Captured (for Ivan's email)

1. **Header vs. line** — measure at line level.
2. **Customer segmentation** — must filter by classification: **Strategic** (Gold + Platinum) vs **Standard** (everyone else), plus All Customers. Underlying classes: bronze/silver/gold/platinum/etc.
3. **Visibility on multiple misses** — show whether a line was impacted multiple times and the reason for each, while still counting as one miss.
4. **Customer-agreed postponements** — TBD whether these still count as a miss (Ivan leans: once there's an OTIF, it counts).
5. **Day-of-impact** — quantify delay days per miss and per reason.
6. **Reclassification / correction** — manage reason-code corrections in JDE (not Excel), with consistent flow-through to Power BI.
7. **Comment field** — ability to record a few lines of context per code (e.g., for an L3, which raw material and the specific reason).
8. **Responsibility mapping** — a maintainable master table mapping reason codes → owning department (Supply Chain, Planning, R&D, Operations, etc.), adjustable as the org changes.
